# 0007: Parsed-command policy for terminal execution

**Status:** Accepted (implementation in Phase 4)

## Context
The agent can run shell commands generated by a model. Silent execution of arbitrary commands
is unacceptable. Blocking everything makes the agent useless.

## Decision
Classify every command into allowed / requires approval / blocked with a `CommandPolicy` that
**tokenizes the command with shell rules** and classifies each segment of a compound command.
The strictest decision wins, and anything the parser cannot understand requires approval. Rules
are ordered data with a human-readable reason, and are configurable per project. Execution uses
`Process` in the project directory with a scrubbed environment, a timeout, process-group
termination and capped output. Details: docs/security/command-execution.md.

## Alternatives
- **Regex on raw command text**: easy to bypass (`r''m -rf`, `;`-chaining, substitutions).
- **Always ask**: approval fatigue, and users would then click through dangerous prompts.
- **Run in a container/VM**: strong isolation, but heavy, slow, and it breaks access to the
  user's toolchain. It may be offered later as an optional mode.

## Consequences
- The policy parser needs thorough table-driven tests.
- Some legitimate complex commands will require approval. This is the intended conservative
  bias.
